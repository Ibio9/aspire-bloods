**The last two rows are the point of this report.** The first of them is hardcoded to zero in `analyteMappingCoverage()` and stays hardcoded: it answers "what does the code claim on its own evidence", and the honest answer is nothing, because nothing in the map was derived from a Randox payload. It must never become a computed number, because every computation available to it would be counting assumptions.

The second is counted from `RandoxAnalyteObservation`, which records the analyte string of every result row that arrives and what became of it. That is evidence rather than assumption, so it may grow. It currently stands at **0** — no delivery has been ingested in the database this ran against.

Everything above the last two rows is the catalogue agreeing with itself. 186 of 186 markers resolving from their own names says that our name index is internally consistent. It says nothing whatsoever about how Randox spell them.

## The whole catalogue, not just the clinical part

The map has to cover every marker Randox can send a result for, which is all of them — a food IgG item and a microbiome proportion arrive on the same payload as a potassium. The clinical figures above are MEASURED plus QUALITATIVE; this is everything.

| Result type | Markers | Answer to one spelling only |
| --- | --- | --- |
| SENSITIVITY | 207 | 205 |
| MEASURED | 164 | 65 |
| GENETIC | 32 | 29 |
| QUALITATIVE | 22 | 21 |
| COMPOSITION | 10 | 9 |

**The SENSITIVITY row is the one to look at twice.** Our catalogue holds every food item with a disambiguating suffix — `Cod (IgG)`, `Casein (IgG)` — because deduplicating by name across categories would otherwise merge `Egg White` into a protein assay. That suffix is OURS, not Randox’s. If Randox print the food name bare, not one of those 207 resolves, and the whole food-sensitivity section of a Signature report lands in the exception queue at once.
That is NOT fixed here by stripping the suffix or by adding 207 guessed aliases, for the same reason nothing else in this file is guessed: the queue catches an absent mapping and nothing catches a wrong one, and `Celery`, `Mustard Seed` and `Egg White` are exactly the names a future allergen panel would reuse. It is written down so the first Signature delivery is checked for it deliberately, rather than discovered as 207 exceptions.

## For Randox

- **The exact analyte strings each panel returns**, as printed in `reportResults.analyte`. One real GetOrderResultDetail payload per panel would confirm or correct the whole map in an afternoon, and would turn the confirmed figure above from a zero into a number.
- **The void and caveat code list.** Unrelated to the map, and the other thing that silently costs results — an unrecognised code withholds one by design. The boot guard still refuses to start with `RANDOX_TRANSPORT=live` while the code map is the checked-in placeholder, and that guard is not to be weakened.
